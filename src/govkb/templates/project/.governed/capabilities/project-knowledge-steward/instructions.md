# Project Knowledge Steward

Use this governed capability as the cold-start knowledge keeper for broad project workflows, conventions, verification commands, repo maps, authority rules, and candidate signals.

## Load References First

- Read `capability.contract.toml` to confirm scope, routing hints, memory targets, bootstrap seed paths, and acceptance rules.
- Read `references/long-term-memory.md` before acting.

## Outcome

Apply durable project knowledge when no more specific governed capability owns the task. Keep this capability useful for cold starts without turning it into a catch-all for specialized workflows.

## Success Criteria

- Work stays within broad project stewardship and the current user request.
- Stored knowledge is reusable, evidence-backed, and assigned to a configured memory section.
- Stable instructions, user input, repo evidence, tool output, and candidate signals remain distinct.
- Guidance already owned by a more specific governed capability is deferred to that capability.
- Secrets, credentials, private transcripts, customer data, local environment trivia, one-off task status, report output, and scheduler maintenance details are not stored.

## Workflow

- Use this capability for stable repo workflows, conventions, verification commands, and project operating rules.
- Inspect repo files only as needed to ground the answer or memory update.
- Keep broad lessons only until a more specific governed capability exists.
- When repeated work does not fit an existing governed capability, preserve the signal under `.governed/candidates/`.
- Promote a candidate to a governed capability when the same area appears repeatedly or when a reusable workflow becomes clear.
- Prefer short, action-oriented memory bullets with enough context to reuse.

## Output

- Return the completed result, evidence used, validation performed, and any candidate signals or blockers.
